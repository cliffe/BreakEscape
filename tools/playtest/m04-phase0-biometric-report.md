## Verdict
Biometric locks work as a mechanic (kit + dusted print opens the door, and the unlock persists server-side across reloads), but are not safe on a main mission's critical path as-is. The print itself is client-only, so a reload costs the player a re-dust, which is recoverable. The real problems are: (a) dusting caps quality at about 0.8, so any threshold at 0.9 can never pass and a threshold of 0.7 is marginal (heavy over-dusting can drop it below, and a low sample cannot be re-dusted without a reload); (b) print-bearing objects hide their own text and observations whenever the player lacks the kit or has not yet dusted them; (c) the only event is a generic minigame_completed with no owner, so scenario logic cannot react to a specific print; (d) the failure message uses the internal owner id and does not tell wrong from missing. A main-path use would need thresholds of 0.7 or lower (use 0.5), a kit given before the first print object, objects whose useful text is not on the print-bearing item, and the player told what to do via an NPC or note.
