**Still needed or still broken:**

- **H1. Controls with no harness verb, driven with DOM `eval`:** the scope-card pairs (worked with `clickControl` by index), the mail client's Create account (an account `<select>` set to `create:freemail` plus the radio and Confirm), the compose-form `<select>`s (template, subject, attach, To, Send as), and the picker pop-ups for blanks (`.mail-picker-option`, `.pretext-picker-option`). OSINT blocks, plan board, report options, page-builder options, triage verdicts, flags, and the SOC board all worked through `mg clickControl` without eval.
- **H2. `converse` for hub NPCs works** (Gareth, Ruth, Tomasz), but it chooses the first unused branch only; it did not stop at a stalled conversation, so no issue.
- **H3. `bootstrap` loops on the end card.** After a reload at the end card, `bootstrap` treats "ENGAGEMENT CLOSED / Return to Missions" as an ordinary blocking overlay and clicks it over and over. The 400-step loop took about 7 minutes (seq 858 to 859, 11:14:43 to 11:21:48) and every dismissal was logged; the page stayed on the end card. The game state was fine afterwards. After the end card, use `brief` rather than `bootstrap`. This is a harness issue, not a game issue.
- **H4. A `brief` or `bootstrap` sent too soon after a reload** fails with `Cannot read properties of null (reading 'x')` until the player sprite exists. A few seconds' wait fixes it.
