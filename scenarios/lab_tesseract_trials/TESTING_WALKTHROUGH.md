## How to use this file

Every answer in this scenario is generated per game (`Mission#generate_scenario_data` renders the ERB once, unseeded). So the steps below say **where to find each input and which recipe to apply**, never a fixed answer. A tester earns each answer in the world, then types it in.

Ids in `backticks` are scenario object, NPC, task or global ids, for the test bridge (`__test.interact('<id>')`, `waitForTask`, `waitForGlobal`; see `docs/test-bridge.md`). Locked containers and rooms are opened by typing the decoded answer in the password or PIN pad. The server checks the unlock method against the lock type, so a wrong method is refused.

**Seed-42 example.** Rendered with `ruby scenarios/lab_tesseract_trials/tools/render_scenario.rb <out.json> 42` from the repo root. The "Example (seed 42)" lines give the values that render produces.

Reproducibility caveat (checked by rendering twice): seed 42 fixes the words, PINs, the Vigenère key, the pigeonhole number, the L10 fingerprint and the tracking token. It does **not** fix the IV, the AES key, the RSA key pairs, the sealed envelopes, the drop box tag, `report.sig` or the leaflet's key fingerprint, because those come from OpenSSL and `SecureRandom`, which `srand` does not seed. For those, read the value from your own run. The answers they produce (`padlock-92`, `8841f594`) are the same every time.

## Findings

- **[TRIGGER UNKNOWN]:** none. Every task has an in-world trigger.
- **[DEAD ZONE RISK]:** none found. Every locked step has its answer behind an earlier lock or in another room, and HaX's hub plus the hint ladder cover each step.
- **Seed 42 is only partly reproducible.** `render_scenario.rb` seeds Ruby's random generator but the RSA keys, AES key and IV come from OpenSSL and `SecureRandom`. Two seed-42 renders differ in 11 fields (the IV, key-dependent ciphertexts, the tag, the sealed envelopes, `report.sig`, the leaflet fingerprint). The password and PIN answers, the Vigenère key, the hole number, the L10 fingerprint and the token match. A QA script that records the seed-42 tag or envelope will not match a fresh render.
- **`DESIGN.md` status line is stale.** It says "Nothing is built yet", and section 8 calls the outcomes "three endings" while the build has four `ending` values (`sent`, `double`, `refused`, `blown`). Section 3 names pinned objects `chalkboard2` and `smartscreen`; the build uses `tom_board` and `cliffe_build_screen` (documented in "Build notes"). The tester should use the built ids above.
- **Ghost's `[Sending it now.]` on the device does not send** (by design, sending is HaX's hub). It reads as a send option and may confuse players.
- **Not exercised:** nothing here was played in a browser. Reconfirm the HaX hub option labels and the timed text spacing in a playtest (`/playtest-scenario`).
