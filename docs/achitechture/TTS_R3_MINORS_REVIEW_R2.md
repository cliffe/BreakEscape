## Minors

1. `scripts/compile-ink.sh:76-79` with `test/unit/break_escape/ink_compiled_staleness_test.rb:107`. When both `X.json` and `X.ink.json` exist (the 8 pairs in `scenarios/test_scenarios/ink`), the script writes only `X.json`. After an edit to one of those .ink files, the staleness test fails on `X.ink.json` and tells the author to run the script, which will not fix it. `InkStoryFile.find` also picks a different target here (it writes the file the storyPath names). Fix: in the script, when both exist, compile once and copy the output over the other (`cp "$json_file" "${ink_file%.ink}.ink.json"`); or delete the unused duplicate in each of the 8 pairs, as was done for the other test scenarios.

2. `app/services/break_escape/ink_story_file.rb:4-9` against `app/services/break_escape/tts_line_extractor.rb:639-652`. The module comment says the lookup is "decided in one place", but the extractor (which the resolver also uses for placed lines and cache stamps) keeps its own `resolve_ink_path`. It lacks the `.json`/`.ink.json` swap and adds two scenario-dir fallbacks. They agree for every current storyPath, so nothing breaks now, but a storyPath naming `X.json` with only `X.ink.json` on disk would be served by `#ink` and silently absent from the batch. Fix: have `resolve_ink_path` try `InkStoryFile.find(story_path, compile: false)` first and keep its fallbacks after it, or add a test asserting both return the same file for every scenario storyPath (the check in this review, as a test).

3. `app/services/break_escape/ink_story_file.rb:63-69`. `-jo` makes inklecate print errors and warnings as JSON on stdout, so `stderr` is empty: a failed compile raises "Ink compilation failed for X: " with no detail and warnings are never logged (verified with a broken .ink). The code moved over unchanged, but it is now the shared path. Fix: drop `-j` (use `-o`, as the script and the staleness test do), or capture stdout and include its `issues` in the log and the raised message.

4. `app/services/break_escape/ink_story_file.rb:17-27`, `:62-63`. The compile writes `output_path` in place with no lock. `#ink` and `#tts` (and chatter, barks, the lazy loader) hit the same storyPath at nearly the same moment after an .ink edit, so one request can read a half-written file and return a JSON parse error or refuse the line. Fix: compile to `"#{output_path}.#{Process.pid}.#{Thread.current.object_id}.tmp"` and `File.rename` it into place, inside a per-path `Mutex` (a class-level hash of mutexes), then re-check `needs_compilation?` inside the lock.

5. `app/services/break_escape/ink_story_file.rb:18`. `Engine.root.join(story_path)` returns `story_path` itself when it is absolute and follows `..`, so a storyPath can name, and with `compile: true` write, any file the server can reach. storyPath comes from mission ERB, not players (the phoneState `storyPath` at `game.rb:3381` is stored but never looked up here), so this is defence in depth, now on two endpoints. Fix: resolve `File.expand_path(story_path, Engine.root)` and return nil unless it starts with `Engine.root.join('scenarios').to_s + '/'` and ends in `.json`; `ink_story_file_test.rb` uses absolute tmp paths, so give the guard an `allowed_root:` keyword (default scenarios) that the tests set to the tmp dir.

6. `app/services/break_escape/tts_expected_lines.rb:220`, `:233` (not in the diff, exposed by it). `Pathname#sub_ext(".ink")` on `X.ink.json` gives `X.ink.ink`, so the "compiled ink older than source" warning and the .ink source list never cover any story stored as `X.ink.json`. With the `X.json` copies deleted, the five test scenarios above now fall entirely into that gap. Fix: `ink = Pathname.new(json.to_s.sub(/(\.ink)?\.json\z/, '.ink'))` at both lines.

## Nits

1. `test/unit/break_escape/ink_compiled_staleness_test.rb:35-37`. inklecate resolves every INCLUDE, nested ones too, against the root story's directory; the test resolves a nested include against the including file's directory, and skips names it cannot find. All 42 current INCLUDEs are flat and same-directory, so no effect today. Fix: pass the root dir down (`File.join(File.dirname(root_ink), name)`) and use `(\S.*?)\s*$` so a name with spaces is not cut short.
2. `app/services/break_escape/ink_story_file.rb:50-54`. `needs_compilation?` looks only at the main .ink's mtime, so in development an edit to `m09_carryover_vars.ink` or `m10_carryover_vars.ink` never triggers a recompile of the stories that include it (the staleness test still catches the committed state). Fix: compare against the newest mtime of the .ink and its includes (reuse the test's `includes` walker, moved into InkStoryFile).
3. `app/services/break_escape/ink_story_file.rb:32-35`. A storyPath ending in `.ink` (or naming a directory) passes `File.exist?` and is returned as the "compiled JSON", so `#ink` answers 500 "Invalid JSON". Fix: return nil from `compiled_json` unless the path ends in `.json` and `File.file?`.
4. `app/services/break_escape/tts_line_extractor.rb:328` against `app/services/break_escape/tts_line_resolver.rb:112-113`. A narrator line that starts with `voice:` keeps its marker in the batch (`!narrator`) but is refused at the endpoint by `found`. No content has one. Fix: drop `&& !narrator`, or exempt narrator results from the `found` refusal; either way batch and endpoint agree.
5. `app/services/break_escape/ink_story_file.rb:62`. The default for `output_path` duplicates the one at `:25` and no caller relies on it. Fix: keep the default in `compile!` only and call `json ? compile!(ink, json) : compile!(ink)` at `:25`.
6. `app/services/break_escape/tts_line_resolver.rb:176`. Every non-host, non-phone lookup now indexes the story twice (once as `voice:` transcripts, once plain) before it can match an ordinary line. Cheap if `canonical` caches its index; if not, try the plain lookup first for non-phone records and the `voice:` one second, which keeps the same result because `found` refuses a marked line anyway.
