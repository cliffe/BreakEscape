## Nits

1. **Section 4, V5 `item_` stem: the classifications are deferred, not enumerated, unlike every other stem.** The plan enumerates and attributes every `npc_`, `workstation_`, `desk_phone_`, `magnet_` and `room_tone_` literal, but for `item_` it names only `item_dropped` (by name, office life) and leaves the rest to "the fixture's first run" (`OFFICE_LIFE_MISSIONS_PLAN.md:313`). Today's tree emits eight other `item_` literals the builder must classify before the fixture is green: `item_consumed` (`consumables.js:216`), `item_gone` (`npc-needs.js:3148`), `item_interact` / `item_interact_1` / `item_interact_2` / `item_interact_3` (`sound-manager.js:48-206`, sound keys), `item_picked_up` (`objectives-manager.js:309`), `item_removed_from_scene` (`interactions.js:41`) and `item_unlocked` (`objectives-manager.js:324`). The plan gives the right direction ("story events, not office life", so exclusion or ignore), and the fixture-as-source-of-truth model (`:315`) means the lists are finalised on the first run before stage 4, so this is safe rather than wrong. Failure scenario if the direction is misread: `item_unlocked` is a core objectives/unlock event, so if a builder treats the `item_` stem as office-life-wide rather than putting `item_unlocked` on the exclusion list, a required task gated on `item_unlocked:<x>` would be mis-handled by V5. Fix: enumerate these eight `item_` literals in section 4 with their files and intended list (all to exclusion or ignore, `item_dropped` the sole office-life name), matching the completeness of the other stems, and name `item_unlocked` explicitly as an exclusion so it is not lost.
