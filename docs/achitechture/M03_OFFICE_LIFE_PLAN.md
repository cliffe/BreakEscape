### Engine findings (checked in code this session)

1. **Hiding at the night turn works with existing fields.** A mapping `{ "eventPattern": "global_variable_changed:clone_call_done", "condition": "value === true", "setVisible": false }` on each new NPC. `setVisible` state is saved and restored on reload (`core/game.js:1811` to `:1816`, `npc-manager.js:354` to `:357`, `npc-sprites.js:228` to `:236`), so no backstop is strictly needed. Add Victoria's room-entry re-hide (`room_entered:reception_lobby` and `room_entered:main_hallway` with `clone_call_done === true`, `setVisible: false`, not `onceOnly`) as belt and braces. A hidden NPC is `blocked` in the needs tick: its job is aborted and it stops (`npc-needs.js:1414` to `:1420`, `isAvailable` :1231), so a staffer hidden mid-use in the hallway just vanishes. Each new NPC adds one saved visibility entry (count it in the sync table). On the first frame `room_entered:<start room>` fires once with `previousRoom` null (`core/rooms.js:3195` to `:3226`); whether NPC mappings are registered by then is unproven, so it is a stage-4 measurement.
2. **Cross-room needs walks are supported**: loaded rooms through open doors (`NPC_NEEDS_SYSTEM.md:51`), `needsRooms` allow list (:119). A cooler in the hallway is usable only once the hallway has loaded. Use `needsRooms: ["reception_lobby", "main_hallway"]`, which keeps both staff out of the exec wing, conference room and server room.
3. **Gap: chatter is voiced over the player's conversations in the same room.** `world.playerHears` (`npc-needs.js:5403` to `:5418`) checks only room, radius, light and line of sight, with no open-minigame check. `npcChatterVoice.say` (`npc-needs-chatter.js:237` to `:265`) has no minigame check either. Exchange lines are voiced at once (`speak`, :5426 to :5432), while pool lines wait for the bubble layer, which draws nothing under a minigame; whether they then play or drop is unverified (`npc-world-bubbles.js:578`). The needs clock does not pause for conversations, only for the VM (`update`, :655 to :667). In m03 the briefing cutscene, the `night_transition` scene and Ffion's conversations all run in reception, the room the pair share, so an exchange could start over them. m02 never hit this, because its pair had their own room. Proposed engine change (E-m03-1, small): `playerHears` returns `overheard: false` while a person-chat or phone-chat minigame is open, so turns become pictures and exchanges wait (E9 keeps them unplayed). It needs unit tests, a focused test scenario and live proof (standing rule). A scenario-only fallback is to post the pair in the hallway and leave reception to Ffion, which loses the long reception dwell.
4. Hostile-leash, KO, `offWhen` and exchange-heard rules are as in m02's plan (E7 to E9 on main).
