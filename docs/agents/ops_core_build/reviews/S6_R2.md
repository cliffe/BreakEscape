## B. New findings

### R2-1 (blocker): a test assembles real identifiers at run time

- **Where:** `test/unit/realism_separation_test.rb:83`.
- **What is wrong:** the "refuses a plausible one" list joins four strings from parts. Joined, the first is the same
  vendor bulletin that R1-S1 was raised for; the second is a four-digit-year advisory id that is real and among the
  best known; the third is the seven-digit article number R1-S1 already asked to be dropped; the fourth is a
  two-digit-year id in a scheme that was issuing ids in that year. The parts are split only so the file's own scan
  (`:88-98`, which reads this file) does not see them. A real id in two halves is still a real id in the repository.
- **Other assembled strings, all invented and not a breach:** `realism_separation_test.rb:63` and
  `validate_realism_skin_test.rb:377-379` (`made_path`) join `exploit`, `area`, `thing`, `probe`, which names no
  module; `validate_realism_skin_test.rb:396` and `:413` join an advisory form with the year 9999. The join there
  is not needed (year 9999 passes the fixture scan as it stands) but does no harm.
- **What the test needs:** four strings that have the realistic form and that `INVENTED_ID` (`:72`) does not accept,
  so that the check is shown to refuse a string that is not plainly invented.
- **Smallest fix:** build them from numbers no scheme has used, computed at run time:

  ```ruby
  far = Time.now.year + 100   # no advisory is numbered a century ahead
  gap = 45                    # the bulletin scheme used two-digit years 98 to 17 only; the other scheme starts at 05
  bad = ["CVE-#{far}-#{4242}", "MS#{gap}-#{123}", "ZDI-#{gap}-#{123}", "kb#{8_000_000 + 4242}"]
  ```

  Each matches the scan's shape and none matches `INVENTED_ID` (the year is not 0000, 9999 or 31, the number is not
  999, the tail does not start 00, 99 or x). The first three cannot name an issued advisory. No seven-digit article
  number can be proved unissued; the one above is in a range far above any issued today, or drop that one probe.
- **My own search of the whole diff** (`1d12d119c..HEAD`, 328 files, client source and JS fixtures included) for
  advisory shapes, framework path shapes, the 17 nicknames and public addresses found nothing real outside this
  line. Every advisory-shaped literal has year 0000 or 9999, bulletin year 31 or 99, or a placeholder tail; every
  path uses invented product words; the nicknames appear only in the deny list.

### R2-2 (major): the history test checks nothing in a shallow checkout, and it is the only guard against a regenerated index

- **Where:** `test/unit/validate_realism_catalog_test.rb:232-250`; `.github/workflows/ci.yml:51` (`actions/checkout@v4`
  with no `fetch-depth`, so depth 1); `scripts/validate_realism_catalog.rb:377-380`, `:397`;
  `docs/ACCESS_AND_NETWORKS.md` N16 ("The unit test also compares the index with every earlier committed version").
- **What is wrong:**
  1. `--first-index` does not skip the comparison when an index exists (probe: a reuse with the flag and the index
     present is still `index_identity_changed`). But `rm` the index, then `--first-index`, writes a fresh index with
     any id removed, renamed or reused, and the run is clean. The script cannot tell a first run from a later one.
  2. So the rule rests on the history test. It reads `git log -- docs/REALISM_CATALOG_INDEX.md` on the ancestors of
     HEAD. In a depth-1 clone that lists one commit, HEAD itself (checked: `git clone --depth 1` of this branch
     lists only the tip), so the test compares the index with itself, passes and does not skip. CI is such a
     checkout. On a developer's full clone the test does work.
  3. `git log -- <path>` simplifies history: an id added on a side branch and dropped in the merge resolution is
     never listed.
- **How to see it:** in a scratch copy of the catalog: validate with `--first-index`; remove an entry; delete the
  index; validate with `--first-index` again: "clean; index written". Then `git clone --depth 1` and count
  `git log --format=%h -- docs/REALISM_CATALOG_INDEX.md`: one line.
- **Smallest fix:** set `fetch-depth: 0` on the CI job that runs `bin/rails test`; in the test, fail (not pass, not
  skip silently) when `git rev-parse --is-shallow-repository` prints `true`; add `--full-history` to the `git log`.
  Reword the N16 sentence to say the comparison needs full history.
