### R3-2 (minor, note for the plan). Link rows can now push a once-only share row out of a small source

`app/models/break_escape/ops_log.rb:816-828` (eviction order), `lib/break_escape/ops_log_events.rb:53-54`.
With link rows never merged, a player who plants and unplugs fills the source to its cap. Eviction
keeps the first row of each event, so the first `SHARE_OPEN` stays, but a later one (the folder row)
is an ordinary ok row and is evicted oldest first. It is written once per folder and account, so it
never returns. In `test_ops_logs` (cap 50) that takes about 23 plant and unplug pairs after the
folder is opened. Bounded and by the cap's design; nothing reads the row but the player. Suggested
fix: none in code; one sentence in 13.8 ("link rows are not merged, so a long plant and unplug loop
can evict older rows of the source, a once-only folder row among them"), or leave.
