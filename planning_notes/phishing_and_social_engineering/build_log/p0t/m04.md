## Regression candidates (DIFFERENT lines)

**Line 36: resume overlay after the reload, and Space/Enter not closing the title.**

What I saw: after `location.reload()` on a game with progress, the title screen did not close on `mg continue` (Space) however long I waited (the page was loaded: `_gameLoaded` true, `_playerClicked` false). A click on the title container closed it, and a "RESUME SESSION?" overlay then covered the game until Resume was clicked. The baseline run recorded neither the overlay nor the stuck title.

Why I do not think Phase 0 caused it, but cannot rule it out from the run:

- `git diff 5a4d0ae7 HEAD` shows no change to `app/views/break_escape/games/show.html.erb`, `public/break_escape/js/ui/session-resume-keys.js`, `public/break_escape/js/minigames/title-screen/*`, or `Game#has_progress?` (`app/models/break_escape/game.rb:38`). The overlay logic (`show.html.erb:318-335`) strips `skip_resume` on every load, so any reload of a game with progress shows the overlay; the key guard (commits `fa72c8d5`, `0275920e`, both ancestors of the baseline's HEAD) lets only Enter through while the overlay is up.
- Phase 0 did touch `public/break_escape/js/core/game.js`, `state-sync.js`, `minigame-manager.js` and the new `social-overlay.js` ("return-to and overlay helper"), which is where I would look first if the overlay's interplay with the title screen changed: `social-overlay.js` and the `minigame-manager.js` hunk (+101 lines). I did not read them (no edits and this run is a comparison, not a diagnosis).
- The likelier explanation is environmental: the baseline note for this step says "no resume overlay", and its first two reload steps (`pressKey Enter` refused, synthetic Enter did nothing) match mine, but its `mg continue` then closed the title in one call. A difference in when the overlay's DOMContentLoaded handler ran relative to the title (the reload here ran under a load average of about 40, against 8.7) could explain a race. I did not re-run the reload on a quiet machine, so I cannot tell a race from a regression. Suggested follow-up: repeat only the reload step (new game, three Vance choices to get progress, `sync`, reload) on :3001 and see whether `mg continue` still fails to close the title; if it does, bisect `91c1ee03` on the title/overlay files above.
