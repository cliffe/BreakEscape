### Flagged decisions, checked

- **P0-F `when` default and lockout storage.** `at: 0` defaults to "above"; the validator's `threshold_when` (`validate_social.rb:502-506`) uses the same rule, so the engine and the lint agree. A permanent (`null`) lockout stored as `-1`, like `until.global`, is fine: `checkLockout` lifts `-1` only when an `until.global` is true, so a permanent lockout never lifts, and the validator rejects `null` unless there is an `alternativeRoute`. That is stricter than the contract (which rejects it only on a critical-path character), and is acceptable for now. Silent lifts emitting change-only events: agreed. The real problem in the threshold logic is R-02.
- **P0-D `openChat: false` for `set_global`.** Agreed. Before the change, `set_global` wrote `gameState` and emitted. It never touched the open chat's story, and S3 allows only the cached-story broadcast as new behaviour. In shipped content the broadcast reaches nothing, because no mapping uses the ink bark path and `getInkEngine` is dead code. The event payload and order (gameState, then emit) are unchanged, and `emitAlways` keeps the re-fire on every call (test at `social-global-writer.test.mjs:100`).
- **P0-M normal exit (`success === true`, not `{aborted:true}`).** Agreed. It matches 00 §6 ("Closing a viewer overlay is a normal exit"). Nothing in shipped code passes `returnTo` or `suspended`, so with neither param the manager behaves as before: `requiresKeyboardInput` keeps the same truthiness, and `_clearSuspend` is a no-op. The gap is R-05.
- **P0-G default step 10 and `window.socialInfluence` lookup.** Agreed. Without a `social.characters` key nothing is imported, `window.socialInfluence` is undefined, and all four new case labels fall through to the old `default` branch (logged as unknown, nothing written), which is today's behaviour for m01 Derek's `#influence:-100` and the hub demos' `#influence_gained:N`. Attribution is weak at some call sites (R-04).
- **P0-I headless id rule and display-name tie.** The id rule (`channels.email`, room NPC wins) matches on server, client and validator, and the Rails tests cover both the narrow SQL `scenario_npc_ids` and `#give_item` (met, not met, wrong item). The remaining gap is the client side of a clash (R-12). The display-name tie is R-01.

### Coordinator's extra item: m07 `assign_tactical_team` lingering in `openTasks`

Not caused by Phase 0. The m07 commit choice (`m07_opening_briefing.ink:287-289`) sets `team_assigned` through the `#set_global` tag. That is the `set_global` case in `chat-helpers.js:456-518`, which this commit did not change and which does not call `applyActions` or `writeGlobal`. `hurt_line_said` comes from the `global_variable_changed:team_assigned` mapping, applied by `npc-manager.js:798` (`config.setGlobal`), which also does not go through `applyActions`. The only callers of `applyActions` are object interactions, the ESD and flag-station minigames and timers, and none of them is on this path. `#complete_task` runs `objectives-manager.js:544` `completeTask`. That marks the task `completing`, awaits `serverCompleteTaskWithRetry`, and sets `completed` only when the POST returns (about `:590`). The two globals are therefore set synchronously, and the task leaves `openTasks` one server round trip later. Three reads inside that window is read timing against server latency, not a reorder. `writeGlobal` is synchronous in any case and adds only a broadcast to an empty cache between the write and the emit.

### Coordinator's second extra item: Space not closing the title after a reload (p0t/m04 line 36)

Verdict: not caused by Phase 0. The title screen listens for Space and Enter on `document` in the bubble phase (`title-screen-input.js:20-43`; it is attached in `title-screen-minigame.js:141`). The session-resume key guard (`ui/session-resume-keys.js`, `installResumeKeyGuard`) listens on `window` in the capture phase. While the RESUME SESSION overlay is showing, it stops every key except Enter with `stopImmediatePropagation`, so Space never reaches the title. That is exactly the run's symptom: `_playerClicked` stayed false, a click (which the guard leaves alone) closed the title, and the overlay was then visible. The difference from the baseline is that the overlay was up at all, not how the title receives keys. P0-T already notes that `show.html.erb` and the guard are unchanged since the baseline commit, and points to a load-time race. Nothing Phase 0 changed is on this path:
- `startTitleScreen` (`title-screen-minigame.js:230`) passes no `requiresKeyboardInput`, `returnTo` or `suspended`. The computed `requiresKeyboardInput` keeps the same falsy value as before, so neither `pauseKeyboardInput` nor its async-import fallback runs.
- `_clearSuspend` acts only on a running minigame whose `params.suspended === true`, and nothing in m04 sets it.
- `endMinigame` changes only behaviour for `_suspendedForChild` and `returnTo`, which the title never has.
- The capture-phase Esc handler belongs to `SocialOverlayScene`, which no shipped scenario starts, and it handles only Escape.
- The new `core/game.js` blocks are `registerHeadlessRecords`, which returns `[]` with no `social` key, and the influence import, skipped with no `social.characters`. Neither touches input or the title.

To confirm, re-run the reload step with the overlay checked: if `#session-resume-btn` is visible before `mg continue`, Space is swallowed by design and Enter is the key to send.

### Coordinator's item: the `superseded minigame instance` warning (p0t/m03.md, DIFFERENT 4)

The new manager code does not change this flow. `#clone_keycard` (`chat-helpers.js:318-385`) sets `window.pendingConversationReturn` and calls `startRFIDMinigame`, which calls `startMinigame('rfid', null, { mode, cardToClone })` with no `returnTo` and no `suspended`. The running person chat has no `suspended` param either, so `startMinigame` (`:66-69`) ends it with the old `endMinigame(false, null)`. In `endMinigame`, `suspendedForChild` is false and `params.returnTo` is undefined, so the path is byte-for-byte the pre-91c1ee03 one: `onComplete`, clear `currentMinigame`, the orphan sweep and the bark drain. The way back is `rfid-minigame.js:418-425` → `returnToConversationAfterRFID` (`:473-`), which starts a new person chat by timer, also without the new params. The warning comes from the old person-chat instance. A deferred `complete(true)` from `scheduleDialogueAdvance` (`person-chat-minigame.js:395`, used by the exit paths at `:1068,1280,1334`) fires after that instance has been replaced. The `base-minigame.js:89-91` guard drops it, as in the m02 and m05 baselines. That timing depends on where the clone tag sits relative to an exit or end in Victoria's ink, not on Phase 0.
