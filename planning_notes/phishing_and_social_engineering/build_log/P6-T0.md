## Failing row

**RP2** "report shows a call line for the service-desk call": `getTestState().report.results.calls` is empty. Cause is in `public/break_escape/js/minigames/engagement-report/report-model.js` lines 133 to 137 (P6-B): it keeps `social.pretextNpcs` entries with `typeof c.id === 'string'` and builds the globals from `c.id`. The lab's entry (and the contract, `00` line 1765, plus `pretext-prep-minigame.js:62` and `person-chat-pretext.js`) keys the entry by `callId` (`service_desk_call`), so the filter drops it and the report never shows the call outcome, the reported flag or the lowest influence. Fix is in the report model (read `c.callId`, fall back to `c.id`), with `social-engagement-report.test.mjs` and its fixture switched to `callId` too. Not fixed here (outside P6-T0 scope).

## Findings, not fixed

- **RP2** above.
- **`bootstrap` cannot leave Ruth's opening chat.** Ruth's `start` falls into a `resume` hub whose first choice loops, and `bootstrap` picks choice 1 every time, so with default settings it spends about 100 s on 90 "cutscene choice 1 of 2" steps and returns `settled: false` with the chat still open and the tutorial prompt not yet raised. The script uses `bootstrap` with `maxSteps: 2`, then clears the chat and the prompt itself in S0. Any later lab script (P6-T) needs the same.
- Two aims the report depends on are `locked` at the start (`report` needs `phish_hard`), yet `results_reviewed` and `findings_paired` still complete from the global mappings while the aim is locked. This is what RP9 and RP10 observed; flagging it in case locked-aim tasks completing early is not intended.

## Limits of the script

- Mail and call results are only checked with injected data (mail) or not at all (calls, see RP2). A real result from a sent phish and a finished call is for P6-T.
- The page line check is a regex (`/ubmitted/`) on the model's `line`, not the exact wording.
- Tab order is checked as in `bridge-1a`: every visible control takes focus, none has a positive tabindex, DOM order is the expected order. Real Tab-key walks are not simulated.
- Reload uses `?skip_resume=1` after `sync`, as in `bridge-4`.
- Scope/plan Close and Esc are each tested once (Close on scope, Esc on plan and report).
