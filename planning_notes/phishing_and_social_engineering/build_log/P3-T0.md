## Limits of the script

- The fresh game has no sent mail, so `own_hampshire` is skipped (`no-sent-record`) and the round is the three authored messages. The `playerSent` card is not shown. A run that sends to Hampshire first would be needed for that.
- This set's `headerPanel` is `open`, so the header panel is always on the message and is not an Esc layer (`detailsOpen` stays false, and opening Explain does not push a layer). Esc-before-overlay is tested on the chip sheet (`chip-sheet`). A set with a collapsed header panel would be needed to test Esc closing that panel.
- Tab order is checked as in bridge-1a: the verdict buttons and chip checkboxes take focus when `.focus()` is called, and none has a positive tabindex. Synthetic key events do not activate a focused button, so Report and the chips are chosen with `click()`.
- Answers were chosen from the scenario's authored truth, through the overlay's own buttons. Nothing was typed from a solution guide or set from the console.
- Reload uses `?skip_resume=1`, as in bridge-1a.
- The blocked-sync and 403 runs are the Phase 3 E2E row, already covered by `tools/playtest/se/triage-sync-regress.js` (P3-C). They are not in this script.
