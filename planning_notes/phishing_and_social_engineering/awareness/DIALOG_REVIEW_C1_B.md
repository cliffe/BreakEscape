## Where a fix has to land so regeneration keeps it

The shells are partly generated. This matters for every fix:

- **Full-episode host ink** (`scenarios/awareness_e{5,6,7}_*/ink/*.ink`): hand-authored. `main()` in both generators builds **only** the defend-only and check shells, not the full episodes, so a direct ink edit here is safe and will not be regenerated away.
- **Defend-only + check-shell host ink**: written by the generators (`gen_e3_e5_shells.py`, `gen_e6_e7_shells.py`) from inline string tuples. Fix the **generator string and re-run it**, or an edit to the shell ink is overwritten on the next build.
- **Triage copy / cards / voicemails / episode strings** in the defend-only and check shells: `defend_only()` and `check()` call `load()` which reads the fragment `awareness/e{5,6,7}/defend.json`. Fix the **fragment and re-run the generator**.
- **Full-episode strings** (brief, flip, debrief, Monday card) are copied from the fragment into `scenarios/awareness_e{5,6,7}_*/scenario.json.erb` but are **not** regenerated by `main()`. A full-episode string fix must be applied to the **shipped `scenario.json.erb`** and mirrored into the fragment `defend.json` so the source of truth stays correct.

## Major

### M1 — E5 full host "done" line crams three lessons into one 44-word bubble
`scenarios/awareness_e5_signin_pages/ink/niamh_doherty.ink:22` (hand-authored ink)

> Niamh Doherty: That's both seats done, thanks. The trick is always the address: our real sign-in page sits on its own domain and your password manager knows it, so read the address bar before you ever type a password. A padlock doesn't make a page ours.

44 words, in one spoken bubble, over the 30-word cap. In a short session a host line this long is skimmed. It also duplicates the Monday card almost word for word (`strings.mondayCard`: "before you type a password, read the address bar. Your organisation's real sign-in page sits on its own domain, and your password manager knows it…"), so the learner gets the full lesson twice. Trim the host line to a warm sign-off and one hook; let the Monday card carry the detail.

Proposed:
> Niamh Doherty: That's both seats done, thanks. The trick is always the address: read the bar before you type a password. A padlock doesn't make a page ours.

(26 words. Fix in the ink directly.)

## Strengths (no change needed)

- **Teaching is correct and consistent.** The hard idea in E5/E6 — a subdomain (`sso.quayholt.example`, `facilities.tarrowby.example`) is the real domain, an added word with a hyphen (`quayholt-sso.example`, `tarrowby-parking.example`) is someone else's site — is explained the same way everywhere, and tied to the password-manager signal and the padlock myth. E7's frame ("Nobody will ask whether a voice sounded real; what counts is what each message asks you to do") is exactly the "verify, don't trust the ear" lesson, and the real tell lives in the voicemail metadata (saved contact vs an unknown `07700 900…` number), not in a guess about the audio.
- **Warm, non-blaming throughout.** Every `noBlameLine` and `defendOnly` conclusion lands the "people who fall for these are not stupid / it was built to look right" message without ever saying "you fell for it". The pre-check host lines deliberately lower test anxiety ("Just do what you'd normally do").
- **Vivid and memorable where it counts:** Kaylee in the yard with a pallet truck; the cloned Ravinder voicemail at ten to five on a Friday with the payment "half set up"; the genuine-but-awkward Lindiwe voicemail that asks for the safe check rather than a bypass.

- Hub structure is sound on all six: one always-available sticky `+` exit, the `hub_quiet` re-entry pattern, `#exit_conversation`, no hard `-> END`.
