## Verdict

The approach fits the engine: one dispatcher listener for triggers, flip-only facts, globals for every
piece of state, authored gates instead of re-locks, and pre-placed hidden foes instead of spawns. The
plan reads the event sources, the KO order and the persistence paths correctly. It is not ready to
build as written. Two packets' proofs (P10-G, P10-H) contradict how the existing tests load modules.
The end of a case has three ordering faults that a builder would ship and a bridge run might miss: an
unconditional `onClose` that concludes a failed mission, conclusion screens that do not wait for the
debrief, and server gates that see the task before the globals. `reveal_hostiles` before a room loads
gives default-strength foes with no health bar. The `phoneNPCs` rule names a key the client never
loads. All of these have small, local fixes. Three of them (R1E-4, R1E-5, R1E-6) should go into §5
now rather than be left to the spikes, because the code already answers what the spikes would test.

Counts: 0 blocker, 8 major, 10 minor.
