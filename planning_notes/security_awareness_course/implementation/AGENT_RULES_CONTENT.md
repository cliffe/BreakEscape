# Rules for content agents (awareness E8 to E20 build)

Kind of game: the awareness product "Incident Simulations: Critical Cases", short education-first episodes for non-technical staff on a neutral corporate skin (`ui_theme: "general"`). No VMs, no combat, no spy framing, no runtime language model. The aim: one lesson a clerk can repeat on Monday, decisions that teach, plain professional voices, a no-blame debrief, about 15 minutes full and 8 defend-only.

Read, in order: `00_README.md` (§3 decisions, §7 do-nots, §9 done); `01_PIPELINE.md` P1, P2 (which keys are erb-only), P3, P7, P11, and its "Pilot notes (E8, 2026-10-29)"; your episode brief in `episodes/`; the module `concepts.md` files it cites (source of truth for teaching); `planning_notes/phishing_and_social_engineering/awareness/HANDOVER.md` §4; `BRAND_SET.md`. The pilot E8 is the worked example: `awareness/e8/{attack,defend,full_only}.json` and `scenarios/awareness_e8_after_the_click/`.

You write (and own) only:
1. `planning_notes/phishing_and_social_engineering/awareness/eN/attack.json`, `eN/defend.json` (P1 shapes; authoring notes in keys starting `_` so they never leak into shells).
2. `eN/full_only.json`: the exact JSON for every full-episode-only key a wiring agent pastes into the full erb (`flipAftermath`, `stepLabels`, `mistake`, `flip`, `sortDrill`, `guess`, `assistant`, `privacyPanel`, `concernForm`, `playerSentAuth`, erb-only strings), each with a `_notes` line saying where it goes. Follow the packet's shape in `02_ENGINE_WORK.md` exactly; if the packet is not yet on main, still follow its spec and say so.
3. The host ink at `eN/ink/<host_id>.ink` (NOT under `scenarios/`: a new `scenarios/awareness_*` folder trips the shell-registry tests for every other agent; the wiring agent moves it). Pattern: `scenarios/awareness_e8_after_the_click/ink/anjali_rao.ink`. Check it compiles with `bin/inklecate -o <scratch>/x.json eN/ink/<host_id>.ink`.
4. `eN/BRAND_ADDITIONS.md`: the P11 brand-set entry (cast with name, role, age, background, varied ethnicity and age; domains and look-alikes; the name-clash grep across `scenarios planning_notes docs`, including names other new episodes and forms already use: Marcus Webb, Marcus Hale, Dermot Lynch, Ayaan Warsame, Reuben Ofori). Do NOT edit `BRAND_SET.md`; the orchestrator folds these in.

Do not touch: other episodes, E1 to E7, the six role check forms, the rule of thumb (quote `AWARENESS_RULE_OF_THUMB_TEXT` from `awareness/awareness_deploy.py` word for word), `scenarios/`, tests, `missions.json`, generators.

Writing rules: UK English, "cyber security" two words, no em or en dashes, plain English, no AI filler, no effectiveness claims, `.example` domains only, no real brands (except the real UK reporting services concepts.md names), Ofcom drama-range phone numbers, no printed variables in host lines (they will be voiced), lines attributed `Name: text`, host lines under 30 words. Attack content stays at template and psychology level: no working payloads, commands or pages; a "copied command" is described in words. Defend set about six items (4 to 8 allowed), with an awkward genuine item so refusing everything doesn't win, and a similar genuine item after a likely miss. Only built card kinds and shared-library tells, or scenario-local tells declared as E8 does (channelTells + flagChips + set `skillNames` + `factorStrings.redFlag`). Check every template × fact combination reads as English (E8 shipped "moving the the SSO move this month ... this month"). Sandbox options must not list the safe option first every time.

Checks: `python3 -m json.tool` on each JSON file; compile the ink; prove the defend set validates by copying the E8 defend-only shell (`scenarios/awareness_e8_after_the_click_defend/scenario.json.erb`) into your scratch folder with your set and strings swapped in and running `bundle exec ruby scripts/validate_scenario.rb <scratch erb> --strict-social --no-graph --skip-ink`.

Shared tree: other agents are working. Never `git stash`, `git checkout -- <file>`, `git reset`. Commit only your files, always as `git commit -m "..." -- <your paths>` (`git add -- <path>` new files first; never a bare `git commit`, even when the index looks clean: another agent can stage files between your check and your commit, and a bare commit sweeps them in or loses yours to theirs), no attribution lines.

Return: files and commit hash; a summary of the attack (or sandbox) artefact, the defend items (id, kind, phish or genuine, tell), the flip and the debrief panels; where the brief was wrong or thin and what you chose; questions for the wiring agent.
